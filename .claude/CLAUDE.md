# claude-code-player

Плагин для Claude Code: показывает трек, который играет в любом приложении. Имя плагина `now-playing` (имена на `claude-` запрещены валидатором), команда `/player`. Автор тестирует на Windows в приложении Claude (десктоп) и присылает скрины и вывод `/player debug`; облако проверить настоящую Windows не может.

## Что умеет (версия 2.1.0)

- Полоса над полем ввода (`AbovePrompt`): кнопки ⏮ ⏸ ⏭, эквалайзер (обычный или живой, на выбор), трек или текст песни, время `1:23 / 3:45`. Положение слева/по центру/справа, размер текста.
- Строчка у модели (`$.ui.status`), только текст, раскрасить нельзя.
- Панель `/player` (хук `ui.render` на `CommandOutput`): все настройки кнопками, палитры, выбор своего цвета (`hooks/picker.tsx`), источники (скрыть приложение), ссылки на формы Issues.
- Текст песни с lrclib.net, слова появляются по одному; по умолчанию выключен, потому что уходят исполнитель и название.
- Палитры: mono, claude (по умолчанию), neon, sunset, rgb, custom; `/player color name|#hex`.
- Эквалайзер: `frames` (по умолчанию) или `live` (только Windows): столбик сразу подскакивает и плавно опускается (`METER_FALLS`), шкала квадратного корня; `/player equalizer frames|live`. Живой в 2.0.1 убирали за резкость и провалы в ноль, в 2.1.0 вернули на выбор с плавностью.
- Статистика `/player stats`, локально в `$.store`, 31 день; считает одно окно из нескольких (аренда `statsOwner`).
- `/player debug`, `/player bug` (диагностика для формы бага, путь пользователя скрыт).
- Платформы: Windows (`helper/now-playing.ps1`), Linux (MPRIS через `busctl`, `hooks/linux.ts`), macOS экспериментально (Spotify и Music через `osascript`, `hooks/mac.ts`, на настоящем Маке не проверено).

## Как устроено

- `hooks/register.tsx` — главный модуль. Система определяется в `platformOf`: путь с `\` → Windows, иначе `uname` (в тестах `$.process.run` не подменён и отказывает → Windows, поэтому старые тесты идут по Windows-пути).
- Windows: PowerShell 5.1 скрипт печатает JSON-строки: `commands` (путь файла команд), `sessions` (все медиасессии), `levels` (пики громкости 10 раз в секунду, большее из двух замеров, для живого эквалайзера), `command`/`ok` (ответ на нажатие). Кнопки: плагин пишет JSON в файл команд, скрипт забирает его переименованием. Скрипт держать ASCII-only.
- Linux/Mac: плагин сам опрашивает раз в секунду (`watchPolled`) и сразу после нажатия.
- Что показывать, решает `pick`: играющее (сначала показанное последним, потом «текущее» Windows), иначе показанное последним. `select` пишет `track` только при заметном изменении (`isSame`, допуск 2 с), чтобы не перерисовывать полосу.
- Живые части — `Client`-модули (`hooks/equalizer.tsx`, `hooks/clock.tsx`, `hooks/lyrics.tsx`): анимируются сами и спрашивают данные через `surface.post` → один хук `ui.message` (второй такой же хук без матчера движок не разрешает). Только на поверхностях `terminal` и `desktop`, на остальных обычный `Text`.

## Подводные камни (все проверены на практике)

- Не задавать `width="100%"` полосе: десктоп её тогда не рисует.
- Любое чтение атома во время отрисовки подписывает на перерисовку; у кнопок при каждой перерисовке новые внутренние идентификаторы, и подсветка под мышкой мигает. Поэтому полоса читает только редко меняющееся, а частое идёт через `Client`.
- `$` нельзя передавать в метод объекта (`obj.fn($)`): валидатор и загрузчик отказывают. Только именованные функции.
- Символ `▄` на Windows берётся из другого шрифта и другой ширины — в кадрах эквалайзера его нет.
- `Text` не хранит `key`; в тестах искать по тексту; у вложенных `Text` внешний текст включает детей.
- `SessionMode` и `PromptHint` на десктопе для трека не годятся (проверено в 1.1.x).
- Тип настроек называется `PlayerSettings` (`Settings` конфликтует с типом claude-code).

## Проверки

- Типы: скопировать `claude-code.d.ts` из скилла plugin-authoring в `.claude-plugin/types/claude-code/index.d.ts` (папка в `.gitignore`), затем `tsc -p .`.
- `claude plugin validate .` и `claude plugin test .` (тесты в `tests/player.test.tsx`, сейчас 47).
- PowerShell-скрипт: установить pwsh для Linux во временную папку, проверить разбор (`Parser::ParseFile`) и прогнать тело скрипта с поддельным `$manager`.
- Linux вживую: `dbus-daemon --session --fork --print-address`, поддельный MPRIS-плеер на node + `dbus-next`, затем `claude -p "/player debug" --plugin-dir .` с этим `DBUS_SESSION_BUS_ADDRESS`.

## Релизы

- При каждой версии обновить: `VERSION` в `hooks/register.tsx`, `.claude-plugin/plugin.json`, значок в `README.md` и `README.ru.md`, запись в `CHANGELOG.md` (оттуда берутся заметки релиза), ожидание версии в тесте `/player debug`.
- Релиз делает GitHub Actions (`.github/workflows/release.yml`) при пуше в `main` с новой версией.
- Готовую версию автор разрешил переносить в `main` самостоятельно (fast-forward с рабочей ветки). Force push блокируется, настройки репозитория и релизы руками облако менять не может.
- Коммиты от имени `playsin <335104183+playsin333@users.noreply.github.com>`, без подписи (`git config commit.gpgsign false`), без строки Co-Authored-By.
- Обновление у автора: Directory → Plugins → Code → ··· у claude-code-player → обновить список → Update → новая сессия.

## Идеи на потом

Живой эквалайзер на Linux (PipeWire/PulseAudio); больше плееров на Mac; обложка альбома (автор пока не решил, куда её ставить). От перевода текста и полоски прогресса автор отказался.
